# 미니 ERP 프로젝트 — 가상 기업 프로필 & 요구사항 정의서

## 1. 가상 기업 프로필

| 항목 | 내용 |
|---|---|
| 회사명(가상) | ㈜한빛전자 (제조·유통업 가정) |
| 연매출 | 약 100억 원 |
| 임직원 수 | 약 65명 |
| 조직 구조 | 본부(3) - 팀(8) 2단계 구조 |
| 결재라인 기준 | 직급 기준 자동 결정 (사원→팀장→본부장, 금액/유형에 따라 대표이사 결재 추가) |

### 조직도(예시)
```
대표이사
 ├─ 경영지원본부
 │    ├─ 인사팀
 │    ├─ 회계팀
 │    └─ 총무팀
 ├─ 영업본부
 │    ├─ 국내영업팀
 │    └─ 해외영업팀
 └─ 물류본부
      ├─ 구매팀
      ├─ 재고관리팀
      └─ 생산관리팀
```

### 결재 유형별 승인 단계 (예시)
| 기안 유형 | 결재라인 | 비고 |
|---|---|---|
| 휴가신청 | 팀장 승인 | 근태 모듈과 연동 |
| 지출결의서 | 금액에 따라 팀장 / 팀장→본부장 / 팀장→본부장→대표이사 | 100만원 미만: 팀장 단독 / 100만~500만원: 팀장→본부장 / 500만원 이상: 대표이사 결재 추가 (ADR-011 — 아래 FR-2-4 참고) |
| 구매요청서 | 지출결의서와 동일한 금액 구간 | 물류본부 한정, 금액 구간은 ADR-014 |
| 품의서(일반) | 팀장 → 본부장 | - |

## 2. 모듈별 요구사항 정의서

각 모듈은 **As-Is 업무 흐름 → 문제점 → FR(기능요구사항)/NFR(비기능요구사항)** 순으로 정리합니다.

### 모듈 1. 조직/사원관리

**As-Is**
엑셀로 조직도와 사원 명부를 관리. 발령(부서이동/승진) 발생 시 엑셀을 수기로 수정하고 관련 부서(인사팀, IT)에 별도 통보.

**문제점**
- 발령 이력이 남지 않아 과거 조직 구조 추적 불가
- 타 시스템(전자결재 등)과 사원 정보가 분리되어 있어 정보 불일치 발생

**FR**
- FR-1-1. 조직은 본부-팀 2단계 계층 구조로 등록/조회할 수 있어야 한다.
- FR-1-2. 사원 정보(직급, 소속 부서, 입사일)를 등록/수정/조회할 수 있어야 한다.
- FR-1-3. 발령(부서이동, 직급변경) 시 변경 이력이 자동으로 기록되어야 한다.
- FR-1-4. 다른 모듈(전자결재, 근태 등)은 본 모듈의 사원/조직 정보를 참조해야 한다.

**NFR**
- NFR-1-1. 조직 계층 정보는 다른 모든 모듈에서 공통으로 참조 가능해야 한다(단일 소스).

---

### 모듈 2. 전자결재

**As-Is**
종이 또는 사내 메신저로 기안 내용을 전달하고 대면/구두로 승인받음. 결재 진행 상황을 문서 작성자가 직접 확인해야 함.

**문제점**
- 결재 진행 상황 실시간 파악 불가
- 결재라인이 기안 유형/조직구조에 따라 달라 수기 관리 시 오류 발생
- 결재 이력 조회 및 감사 추적 어려움

**FR**
- FR-2-1. 기안 유형(휴가신청/지출결의서/구매요청서/품의서)별로 결재라인이 자동 구성되어야 한다.
- FR-2-2. 결재자는 승인/반려 처리를 할 수 있고, 반려 시 사유를 입력해야 한다.
- FR-2-3. 기안자는 본인 문서의 결재 진행 상태(대기/진행중/승인/반려)를 조회할 수 있어야 한다.
- FR-2-4. 지출결의서는 금액 구간(100만원 미만: 팀장 단독 / 100만원 이상 500만원 미만: 팀장→본부장 / 500만원 이상: 팀장→본부장→대표이사)에 따라 결재 단계가 자동으로 늘어나야 한다. *(변경 이력: 최초안은 "부서 예산의 80% 초과 시 대표이사 결재 추가"였으나, 예산 소진율은 부서·시점에 따라 변동하는 값이라 결재라인처럼 상신 시점에 고정되어야 하는 값과 결합하면 조직 개편·예산 재배정 시 이미 상신된 문서의 결재라인 해석이 흔들릴 위험이 있어, 고정된 금액 구간 기준으로 단순화했다. 예산 소진율 자체는 FR-4-3/FR-4-4가 별도로 다룬다. 근거: ADR-011)*
- FR-2-5. 휴가신청 승인 완료 시 근태 모듈에 자동 반영되어야 한다.
- FR-2-6. 구매요청서 승인 완료 시 재고/구매 모듈에 구매 내역이 생성되어야 한다.

**NFR**
- NFR-2-1. 결재 상태 변경 시 관련자에게 실시간(또는 준실시간)으로 알림이 전달되어야 한다.
- NFR-2-2. 권한 없는 사용자는 타 부서 결재 문서를 조회할 수 없어야 한다.
- NFR-2-3. 모든 결재 이력은 수정 불가(append-only) 형태로 보관되어야 한다.

### 모듈 3. 근태관리

**As-Is**
출퇴근은 수기 서명 대장으로 기록. 휴가는 팀장에게 구두 승인 후 엑셀 대장에 기록.

**문제점**
- 휴가 승인 이력과 실제 근태 반영이 분리되어 있어 이중 관리 발생
- 연차 잔여일수를 실시간으로 파악하기 어려움

**FR**
- FR-3-1. 사원은 출퇴근 기록을 등록/조회할 수 있어야 한다.
- FR-3-2. 휴가신청은 전자결재 모듈을 통해 상신되며, 승인 완료 시 본 모듈에 자동 반영되어야 한다.
- FR-3-3. 사원별 연차 잔여일수를 조회할 수 있어야 한다.

**NFR**
- NFR-3-1. 근태 데이터는 전자결재 모듈의 승인 결과와 일관성이 유지되어야 한다.

---

### 모듈 4. 예산/지출관리

**As-Is**
연초에 부서별 예산을 엑셀로 배정하고, 지출 발생 시마다 회계팀이 수기로 예산 소진율을 계산.

**문제점**
- 실시간 예산 소진율 파악 불가로 예산 초과 지출 사후에 발견되는 경우 발생
- 지출 결의와 예산 집행이 분리되어 있어 대사(matching) 작업에 시간 소요

**FR**
- FR-4-1. 부서별/연도별 예산을 배정/조회할 수 있어야 한다.
- FR-4-2. 지출결의서(전자결재)가 승인되면 해당 부서 예산에서 자동으로 차감되어야 한다.
- FR-4-3. 부서별 예산 소진율(%)을 조회할 수 있어야 한다.
- FR-4-4. 예산 소진율이 80%를 초과하면 화면에 경고를 표시하고, (예상)소진율이 100%를 초과한 상태에서 500만원 미만 지출을 상신하려 하면 상신 자체를 차단해야 한다. 100% 초과 상태에서 500만원 이상 지출은 예외 승인 사유를 입력해야만 상신할 수 있다. *(변경 이력: 최초안은 "80% 초과 시 결재 단계 추가 요청(FR-2-4 연동)"이었으나, FR-2-4가 금액 구간 기준으로 바뀌면서(ADR-011) 예산 소진율과 결재라인을 직접 연동하지 않는 대신, 예산 모듈 자체의 상신 게이트로 통제하는 방식으로 대체했다.)*

**NFR**
- NFR-4-1. 예산 차감은 지출결의 승인 트랜잭션과 함께 원자적으로 처리되어야 한다(정합성 보장).

---

### 모듈 5. 재고/구매관리

**As-Is**
재고는 창고 담당자가 엑셀 대장으로 관리. 구매요청은 구두 또는 메신저로 전달 후 팀장이 별도로 발주처에 연락.

**문제점**
- 실물 재고와 장부 재고 간 불일치 발생
- 구매요청부터 발주까지 진행 상황을 추적할 수 없음

**FR**
- FR-5-1. 품목별 재고 현황(입고/출고/현재고)을 조회할 수 있어야 한다.
- FR-5-2. 구매요청서(전자결재) 승인 완료 시 구매 내역이 자동 생성되어야 한다.
- FR-5-3. 입고 처리 시 해당 품목의 재고 수량이 자동으로 증가해야 한다.
- FR-5-4. 영업/매출관리 모듈에서 수주 확정 시 재고가 자동으로 차감되어야 한다(FR-6-3 연동).

**NFR**
- NFR-5-1. 재고 수량이 음수가 되는 트랜잭션은 허용되지 않아야 한다.

---

### 모듈 6. 영업/매출관리

**As-Is**
영업사원이 개인 엑셀로 수주 내역을 관리하고 월말에 회계팀에 취합하여 전달.

**문제점**
- 실시간 매출 현황 파악 불가
- 수주와 재고 차감이 연동되지 않아 재고 부족 상태에서도 수주가 발생하는 경우 존재

**FR**
- FR-6-1. 거래처 정보를 등록/조회할 수 있어야 한다.
- FR-6-2. 수주(주문) 등록 시 재고 모듈에서 가용 재고를 확인해야 한다.
- FR-6-3. 수주 확정 시 재고가 자동 차감되고, 매출 데이터가 생성되어야 한다.
- FR-6-4. 월별/부서별 매출 현황을 조회할 수 있어야 한다.

**NFR**
- NFR-6-1. 가용 재고보다 많은 수량의 수주는 시스템이 사전에 차단해야 한다.

## 3. 모듈 간 연동 관계 요약

```
조직/사원관리 (기반)
      │
      ▼
  전자결재 (코어) ──▶ 근태관리 (휴가승인 반영)
      │
      ├──▶ 예산/지출관리 (지출결의 반영, 초과시 결재단계 추가)
      │
      └──▶ 재고/구매관리 (구매요청 반영) ◀── 영업/매출관리 (수주시 재고차감)
```
